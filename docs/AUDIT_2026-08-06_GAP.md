## 1. The mismatch nobody has named

The video's system trades **MNQ** — Micro E-mini Nasdaq futures — with intraday strategies
(`MOM 15m thr1.5 2R cut12:00`: 15-minute bars, 1.5 threshold, 2R target, 12:00 time cut).

This repository is built for **NSE and US cash equities on daily bars**. The instrument catalog
is 40 stocks. The backtest engine is decide-on-close / fill-next-open, daily.

These are different products. A 15-minute futures scalper and a daily equity screener share
vocabulary and almost no machinery. This is worth an explicit decision rather than drifting
between the two, and it explains why the build can feel like it is aiming at nothing in
particular.

## 4. Why it feels slow

Candidate causes, none yet measured:

1. Every page is `force-dynamic` with `revalidate = 0` — nothing is cached, every navigation is a
   full server render plus database reads.
2. `/dashboard` was measured at **1,184 ms** server-side in your own log.
3. `SystemPulse` polls `/api/quantcore/status` continuously — visible in your log as a steady
   stream, and the quant core is absent, so every poll is wasted.
4. Provider fetches to Yahoo are timing out at 10s each; any page touching quotes inherits that.
5. `AutonomyTicker` adds a cycle every 15 minutes on top.

---

## 5. Kronos, and the model question

**Kronos is not integrated in any working sense.** What exists: a typed reader, a persistence-
baseline scorer, a request manifest, a runner spec. What does not exist: the model, a Python
process, a forecast file, or a single forecast ever read. `/data-quality` correctly reports
`RESOURCE_NOT_PROVIDED`. That is honest, and it is also nothing.

**On Fable 5:** that is a Claude Code model selection (`/model fable`), not something this
codebase can call. The app deliberately has no model runtime — you call the app through MCP, it
does not call a model. Switching my model changes how *I* reason about your code; it does not
add a capability to the product. If you want a model *inside* the product making trading
decisions, that is a different architecture and worth deciding deliberately.

## 6. What I would do, in order

1. **Decide the instrument.** MNQ intraday or NSE/US daily equities. Everything downstream
   depends on it and the two are not compatible.
2. **Make one strategy actually testable.** Author a spec using only derivable features, rehearse
   it, run the battery on it. Until that exists, every screen is empty for a good reason and the
   product cannot be judged.
3. **Star Map.** The data exists; the visual does not. Highest visible return.
4. **Validation funnel** with survivor counts.
5. **Ingestion that runs** — even two sources genuinely pulling would make the research half real.
6. **Performance pass**: stop the quantcore poll when the core is absent, cache what is static.
7. Then the particle brain and milestones — showpiece, and honest only once the substance is there.

### BUG-1 · `/watchlist` returns 500 — CONFIRMED, root-caused

```
TypeError: Cannot read properties of null (reading 'toFixed')
  at WatchlistManager
```

`components/watchlist/WatchlistManager.tsx:154` guards `item.quote && (...)` — the *object*.
Line 159 then calls `item.quote.changePct.toFixed(2)`, and `changePct` is `number | null`. A
quote that arrives with a null field passes the guard and crashes the render.

This is the "missing is not zero" failure inverted: missing does not render as zero here, it
takes the page down. `price` on line 156 has the same shape and will crash the same way.

### BUG-2 · Watchlist links to a URL the analyze page rejects

`WatchlistManager.tsx:161` builds `/analyze/${item.ticker}` with a bare symbol (`NVDA`).
`parseInstrument` rejects bare symbols — it needs `US:XNAS:NVDA`. Every "Analyze →" link on
that page is dead.

### BUG-3 · `SystemPulse` polls a resource that is known absent

Every page carries `SystemPulse`, which polls `/api/quantcore/status` continuously. The quant
core is not on this machine, so every poll is wasted work on a fixed interval, on every open tab.

## 6c. Trading as the owner — the finding that explains everything

I placed a paper order the way you would: open `/paper`, accept the defaults, press
**PLACE BUY PAPER ORDER**.

```
REJECTED   BUY 1 US:XNAS:AAPL   STALE   -   $0.00
```

The order ledger says why:

| id | side | status | reason | quote | quality |
|---|---|---|---|---|---|
| 4 | BUY | **FILLED** | US_EQUITY_2026_01 | 311.53 | LIVE |
| 3 | SELL | REJECTED | `INELIGIBLE_QUOTE` | 312.50 | **STALE** |
| 2 | SELL | REJECTED | `INELIGIBLE_QUOTE` | 312.50 | **STALE** |
| 1 | BUY | REJECTED | `INELIGIBLE_QUOTE` | 312.50 | **STALE** |

Nineteen orders exist. There is a real position — 5 AAPL at 311.6858 — and real cash: $98,441.57
of a $100,000 account. **Paper trading works.** It filled when the quote was `LIVE`.

It rejects when the quote is `STALE`, which is *correct*: filling a simulated order against a
price that may be minutes old would manufacture a profit or loss that never existed, and every
forward observation built on it would be worthless.

**And on this machine the quote is nearly always stale**, because Yahoo is timing out — the
`UND_ERR_CONNECT_TIMEOUT` flood in the server log. So the engine correctly refuses almost every
order, and from the owner's chair the button does nothing.

### This is the synthesis of the whole complaint

The system is **correct and unusable at the same time**:

1. It refuses for a good reason.
2. It states the reason as one word, `STALE`, next to `$0.00`.
3. It does not say what stale means, why it matters, that the cause is the data feed rather than
   the order, or what to do about it.
4. The underlying cause — an unreachable provider — is visible in `/data-quality` on a different
   screen that the person pressing the button has no reason to visit.

Every "nothing works" observation in this project has this shape. The machinery is right; the
surface does not explain itself; and the data source it all rests on is not reliably reachable
from this network.

### BUG-4 · A rejection that cannot be acted on

`PaperOrderTicket` renders `REJECTED · STALE · $0.00`. It should say something closer to:

> **Not filled — the price is too old to trade against.**
> The last quote for AAPL arrived N minutes ago and this deployment could not refresh it.
> Filling at a stale price would invent a profit or loss that never happened.
> *Provider Yahoo is unreachable — see Data.*

Same event, same refusal, and the difference between a dead button and a system teaching someone
how markets actually work.

### BUG-5 · `$0.00` is displayed where no price exists

A rejected order has no fill price. Rendering `$0.00` states a number that is not merely unknown
but false — the same "missing is not zero" failure the panel-state vocabulary exists to prevent,
in the one place a user is most likely to be looking.
